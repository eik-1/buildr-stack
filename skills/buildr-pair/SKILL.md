# Pair with the owner

Read the selected roadmap outcome and relevant source. Confirm the
baseline from code and evidence. Give the complete day's outcome and a short
outline once, then work one step at a time.

For the current step:

1. Explain how the existing flow reaches the file they will change.
2. Name the file and smallest edit, with the purpose and a concrete hint. Explain
   inputs, outputs, and the important invariant. Do not paste the complete answer.
3. Let the user attempt it. If they ask a question, answer it and continue the same
   step. If they ask you to implement it, complete that portion without asking again.
4. Read their actual edit, explain necessary corrections, and run or describe the
   focused check before advancing. Do not claim code was reviewed from a verbal
   "done" if you have filesystem access and can inspect it.

Keep explanations proportional to their experience. Define unfamiliar terms
using the current code. Do not hide uncertainty behind a long tutorial or turn a
repetitive task into homework when the owner asks you to take over.

At a pause, update the roadmap with completed steps, check results, and the exact
next action. Preserve the distinction between finished code and a
verified outcome. A request for teaching never authorizes paid calls or publication.
